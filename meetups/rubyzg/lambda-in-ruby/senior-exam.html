Part 1: Ruby and runtime contracts

10 points

1. Separate the two lambdas

Predict the behavior of the two calls and explain return behavior for a lambda versus a plain Proc. Then state exactly how much this teaches us about AWS Lambda architecture.

loose = proc { |x| x }
strict = ->(x) { x }
loose.call(1, 2)
strict.call(1, 2)
10 points

2. Trace cold, warm, and failed invocation

A container-image Rails function receives request A in a new environment, request B through the same warm environment, then request C times out. Describe initialization, handler calls, global objects, /tmp, freezing, reset, and what request D may observe. Separate guarantees from possible reuse.

Part 2: HTTP and Rack

10 points

3. Translate a request

An API Gateway HTTP API v2 event contains requestContext.http.method, rawPath, rawQueryString, headers, cookies, body, and isBase64Encoded. Map these to the Rack request contract. Then map [201, {"content-type" => "application/json"}, ["{\"ok\":true}"]] back to an integration response.

10 points

4. Explain why Puma disappears

Trace one HTTP request through API Gateway and Lamby into Rails. Explain why Lamby does not need Puma, where concurrency comes from, and which normal web-server responsibilities still need an owner.

10 points

5. Compare three HTTP front doors

Choose between a Function URL, API Gateway, and ALB for a private Rails admin application already deployed in a VPC. It needs corporate authentication, ten routes, no public anonymous access, and steady low traffic. State what facts you must confirm before choosing and why no service wins by definition.

Part 3: state, database, and jobs

10 points

6. Review global state

CURRENT_USER = nil
S3 = Aws::S3::Client.new

def handler(event:, context:)
  CURRENT_USER = event["user"]
  S3.put_object(bucket: ENV["BUCKET"], key: CURRENT_USER, body: "ok")
end

Find the Ruby error and the Lambda design error. Rewrite the state handling. Explain which objects are reasonable to reuse across warm invocations.

10 points

7. Pick a database path

A Rails function scales from 5 to 600 concurrent environments during a sale. The Aurora database accepts 300 connections. Compare direct mysql2 connections, RDS Proxy, and the RDS Data API. Recommend an investigation and safe initial configuration. Include pool sizing, transaction behavior, latency, IAM, and failure modes.

10 points

8. Stop duplicate fulfillment

An SQS-triggered Lambda marks an order shipped and calls a carrier. The carrier accepts the label, but Lambda times out before SQS receives batch success. Explain the next delivery and design one logical shipment per order. Include visibility timeout, idempotency, partial batch failure, and the dead-letter queue.

Part 4: performance and architecture

10 points

9. Design a cold-start experiment

A teammate says increasing memory from 1,024 MB to 1,792 MB and enabling YJIT cut Rails latency by 40 percent. Design an experiment that separates cold initialization, warm handler time, HTTP integration time, YJIT boot cost, and cost per request. State which percentiles and workload details belong in the report.

10 points

10. Choose the boring architecture

A Rails application has steady traffic, Action Cable, 90-second report requests, PostgreSQL, and four engineers who already run Kamal on two virtual machines. A proposal moves the whole app to Lambda for "automatic scale and no servers." Decide. Identify any bounded pieces that may still fit Lambda and the evidence required before moving them.

Submission checklist

  • The answer distinguishes Lambda container images from ordinary container servers.
  • Rack input and output shapes are explicit.
  • Warm reuse is an optimization, never correctness.
  • Every queue side effect survives duplicate delivery.
  • The architecture decision includes complete-system cost and limits.
