Translate the AWS and Ruby nouns

This talk crosses three vocabularies: Ruby, web servers, and Amazon Web Services, or AWS. Define the nouns before comparing products.

AWS Lambda
A service that starts your configured code when an event arrives, gives one invocation to one execution environment at a time, and bills according to configured resources and execution duration. "Serverless" means AWS operates the underlying hosts. Your code still runs on servers.
Invocation
One request for Lambda to run the handler with one event and context object. An HTTP request, an SQS batch, or a scheduled event can each cause an invocation.
Execution environment
An isolated place containing the Ruby runtime, your loaded code, memory, and temporary disk. AWS may reuse it for several invocations, then remove it without notice.
Runtime
The Ruby interpreter plus the Lambda integration code that receives an AWS event, creates Ruby objects, calls your handler, and sends its result back.
Rack
Ruby's web application calling convention. A Rack application receives one environment Hash and returns an array containing HTTP status, response headers, and a body.
Puma
A long-running Ruby web server. It listens on a network socket, turns incoming HTTP requests into Rack calls, and manages threads or worker processes.
HTTP and HTTPS
Hypertext Transfer Protocol is the request and response language of the web. HTTPS is HTTP protected by encrypted Transport Layer Security.
API Gateway, ALB, Function URL
Three ways HTTP can reach Lambda. API means Application Programming Interface. API Gateway is an API management service. ALB means Application Load Balancer, a service that routes HTTP traffic. URL means Uniform Resource Locator, the address used to reach something on the web. A Function URL is a direct HTTPS endpoint attached to one function.
JSON
JavaScript Object Notation, a text format for nested objects, arrays, strings, numbers, Booleans, and null. AWS commonly serializes event payloads as JSON before the Ruby runtime decodes them.
SQL and IO
Structured Query Language is used to query and change relational databases. Input and Output, written IO in Ruby, is the common interface for reading or writing a stream of bytes.
CPU
Central Processing Unit, the processor that executes instructions. Lambda allocates more processor capacity as configured memory increases.
SQS
Simple Queue Service. Producers store messages and Lambda can poll the queue on your behalf, then invoke your function with a batch.
RDS and S3
Relational Database Service runs managed relational databases. Simple Storage Service stores durable objects under bucket and key names.
IAM
Identity and Access Management. Policies say which AWS actions a function or caller may perform on which resources.
ECR
Elastic Container Registry, AWS's storage service for container images. Lambda resolves an image tag to a fixed image digest when you deploy.
VPS
Virtual Private Server, a rented virtual machine that your team configures and keeps running.

The naming collision is your front door

Ruby's lambda creates a Proc object. "Strict arity" means calling it with the wrong number of positional arguments raises ArgumentError. A plain Proc usually discards extra arguments and fills missing ones with nil. A return inside a lambda returns from the lambda itself. A return inside a non-lambda Proc attempts to return from the method that created the Proc. AWS Lambda is unrelated: it is the managed execution service defined above.

The useful connection is a visible input contract. AWS recommends a Ruby handler with event: and context: keyword arguments. event holds the caller's payload, commonly decoded from JSON into a Hash. context describes this invocation, including its request ID and remaining time. The return value must match the chosen event source. An HTTP integration expects status, headers, and body fields, while an asynchronously invoked function may return a value nobody reads.

loose  = proc   { |x| x }
strict = lambda { |x| x }

loose.call(1, 2)  # => 1
strict.call(1, 2) # ArgumentError

def handler(event:, context:)
  { statusCode: 200, body: "hello" }
end

Two things named Sam

One Sam is a Ruby object that checks how many parcels you hand it. The other Sam owns a warehouse that wakes a worker when a parcel arrives. They are not related. Both reject a parcel that breaks the expected label or shape, which makes the name collision a useful opening joke.

Do not stretch the analogy

A Ruby lambda's strict arity does not explain AWS Lambda's architecture. Use the collision for thirty seconds, then move to events, execution environments, and Rack.

What happens during an invocation

A Lambda function is code plus configuration such as memory, timeout, permissions, environment variables, and handler name. A zip deployment contains Ruby files and gems for an AWS-managed Ruby runtime. A container-image deployment packages the Linux user-space files and runtime client, but AWS still controls the machine and invocation lifecycle. When no suitable warm environment exists, Lambda creates one, starts Ruby, loads code outside the handler, and then calls the handler. It may freeze and reuse that environment, but it promises neither how long reuse lasts nor which later request reaches it.

request or event source | v AWS Lambda service | +-- create execution environment when needed | | | +-- start Ruby runtime | +-- load gems and application INIT | +-- call handler(event:, context:) INVOKE | +-- possibly freeze and reuse WARM | +-- return, error, or timeout

The Runtime API is a local HTTP interface inside the environment. The Runtime Interface Client, usually shortened to RIC, asks that API for the next event, converts it to Ruby objects, invokes the configured method, then posts a response or error. AWS Ruby base images already include the client. A different base image must install it and arrange for it to start. This request loop makes an image Lambda-compatible. It does not expose an ordinary public container port.

Initialization and reuse

# Loaded during initialization and reused if the environment stays warm.
require "json"
S3 = Aws::S3::Client.new

def handler(event:, context:)
  S3.put_object(bucket: ENV.fetch("BUCKET"), key: event.fetch("key"), body: "ok")
  { ok: true, request_id: context.aws_request_id }
end

Creating clients outside the handler can reuse connections and configuration. Mutable global request state can leak across warm invocations. The safe rule is to cache immutable configuration and thread-safe clients, never user-specific state.

Cold versus warm

"Cold start is not a different kind of request. It is a request that must pay for an execution environment and application initialization before handler work begins."

How an HTTP event becomes Rails

Rack is the small agreement between a Ruby web server and a Ruby web application. The environment Hash contains request facts under standard keys. REQUEST_METHOD might be GET, PATH_INFO might be /orders/42, and rack.input is an IO-like object containing the request body. The application returns a three-item array: an integer HTTP status, a Hash of response headers, and an object that yields body strings.

API Gateway, a Function URL, and an Application Load Balancer each encode an HTTP request as a documented AWS event Hash. Their payload versions and fields differ. Lamby recognizes the event shape, creates the Rack environment, calls Rails, consumes the returned body, and builds the response shape required by that same AWS integration.

browser | HTTP v API Gateway, Function URL, or ALB | AWS event hash v Ruby handler / Lamby | Rack env hash v Rails Action Dispatch | [status, headers, body] v Lamby converts to integration response | v browser

The translation, simplified

def event_to_rack(event)
  body = event["body"].to_s
  {
    "REQUEST_METHOD" => event.dig("requestContext", "http", "method"),
    "PATH_INFO"      => event.fetch("rawPath"),
    "QUERY_STRING"   => event.fetch("rawQueryString", ""),
    "rack.input"     => StringIO.new(body),
    "rack.url_scheme" => "https"
  }
end

status, headers, body = Rails.application.call(event_to_rack(event))

The example omits important edge cases. "Normalize headers" means turning AWS's header representation into Rack's HTTP_* keys. Base64 decoding recovers binary request bytes that cannot travel directly in JSON text. Multiple cookies or repeated query parameters must not be accidentally collapsed. The Rack body can stream chunks, while a Lambda proxy response commonly needs one collected body value. A real adapter handles these conversions and closes the Rack body if required.

A plug adapter

Rails speaks Rack-shaped plugs. AWS sends an event-shaped plug. Lamby changes the prongs. It does not rewrite Rails, and it does not need Puma to listen on a port.

Why no Puma?

Puma opens a TCP socket and waits for HTTP connections. Lambda's service already waits for incoming events. Lamby receives one event inside the invoked handler and calls Rails.application.call in the same Ruby process. If ten requests must run concurrently, Lambda can create or reuse ten execution environments. AWS documentation says one standard function environment handles one invocation at a time. Concurrency therefore counts simultaneous environments, not Puma threads inside one environment.

Three architectures that should not blur together

ApproachWhat runs after an event arrivesGood starting use
Plain Ruby handlerThe handler reads the event and calls ordinary Ruby objects. Rails never boots.A webhook, image job, scheduled task, or queue consumer with little framework dependence.
LambyThe handler translates the event directly to Rack and calls Rails in the same process.An existing Rack application whose routes and controllers are the product.
Jets Mega ModeThe parent function starts a separate Rack server process under writable /tmp, then sends the request to that child.A Rails application using the Jets deployment system when its compatibility approach is worth the extra boot work.

A subprocess is a second operating-system process started by the first. A proxy receives a request and forwards it somewhere else. Jets Mega Mode uses both: the Lambda handler process forwards work to its child Rack server. /tmp is "ephemeral," meaning its files can survive a warm reuse but vanish when AWS removes the environment. Lamby takes the opposite route and calls Rack without a child server.

ALB versus API Gateway

Custom Ink chose an Application Load Balancer for early Lamby use because it needed HTTP forwarding rather than a separate API product. API Gateway can add authorizers that decide whether a caller is allowed, stages that separate deployed API versions or environments, request transformations, quotas, and other API controls. A Function URL is a direct HTTPS address for one function with fewer management features. There is no universal winner. Write down authentication, private-network access, route count, payload and timeout limits, traffic, and required API controls, then compare current pricing for that exact design.

The Custom Ink arc

The order makes the case useful. A 2014 attempt to split a Rails system into fashionable microservices failed and was rolled back. In 2017, a bounded image-processing workload moved to Lambda and reportedly cut that workload's cost by about 90 percent. "Bounded" means the job had a clear input, output, and ownership line. Ken Collins then explored whether the existing Rack contract could host the larger Rails app. The evidence supports trying a contained workload first. It does not prove that serverless wins for every monolith.

Rails dependencies do not disappear

Active Record without a MySQL socket

Active Record normally asks a database adapter gem such as mysql2 to maintain network connections and speak the database protocol. Custom Ink's Aurora Serverless adapter instead called the RDS Data API, an AWS HTTPS endpoint that accepts a SQL statement plus identifiers for the database cluster and stored credentials. The adapter translated Active Record operations into those API calls and translated rows back. Rails code still used models, but the Lambda process did not hold a normal MySQL socket.

production:
  adapter: aurora_serverless
  database: app_production
  resource_arn: <%= ENV.fetch("DB_CLUSTER_ARN") %>
  secret_arn: <%= ENV.fetch("DB_SECRET_ARN") %>

An ARN is an Amazon Resource Name, a string that identifies one AWS resource. resource_arn identifies the database cluster. secret_arn identifies credentials stored in Secrets Manager. IAM policy must allow the function to call the Data API and read that secret.

This avoids a pool of direct sockets inside short-lived function environments, but every query becomes an API operation. Measure request latency, transaction support, response-size limits, SQL compatibility, and failure behavior against the current Data API. With conventional Aurora or RDS connections, RDS Proxy sits between functions and the database and reuses backend connections. "Multiplex" means several short client connections can take turns using a smaller set of database connections when transaction state permits. Rails still needs a sensible pool size, commonly one connection per single-invocation environment.

Jobs without a polling Sidekiq process

A Sidekiq server stays alive and repeatedly asks Redis for another job. With an SQS event source mapping, AWS performs the polling. It reads available queue messages and invokes Lambda with a batch. A Lambda adapter such as Lambdakiq maps Active Job's Ruby interface onto that delivery model.

A visibility timeout is the period after SQS hands out a message during which other consumers cannot see it. If Lambda does not report success before the period and retry rules finish, the message becomes visible again. A poison message is one that repeatedly fails for its content, not because of a temporary outage. A dead-letter queue stores such messages after a configured receive count so operators can inspect them. Standard SQS queues can redeliver and do not promise strict order. FIFO queues add ordering and deduplication within documented limits.

Duplicate work is normal

The database write can succeed just before the process crashes. Because AWS did not receive success, it can deliver the message again. Give the business operation a stable idempotency key, or enforce a unique database key, so both attempts produce one result. Return success only after the durable write you care about has completed.

Filesystem and process assumptions

Write scratch files under /tmp. They are a cache, not durable storage. Put uploads that must survive environment removal in S3 or another persistent service. Finish background work before the handler returns because freeze and reuse timing is outside your control. WebSockets keep connections open across requests, so route Action Cable through infrastructure built for persistent connections. Run database migrations once in the deployment pipeline, not once per function environment during boot.

Cold starts are a boot budget

A cold start includes work that a warm reuse can skip: obtaining code, preparing an isolated environment, starting Ruby, requiring gems, and running code outside the handler. Rails then loads framework configuration, routes, initializers, and application classes. AWS reports initialization and invocation data in logs. Measure end-to-end caller latency as well, because it also includes the HTTP integration and network.

Do not rely on an average alone. The median, or p50, is the middle request. The p95 is slower than 95 percent of requests and exposes occasional initialization more clearly. "Scale-out" means AWS adds execution environments to handle more simultaneous invocations. A burst can therefore create several cold starts at once.

Why enable YJIT after boot?

YJIT is Ruby's method-based Just-In-Time compiler. It turns frequently executed Ruby methods into machine instructions while the program runs. Rails initialization executes many paths once, so compiling them can spend time and executable memory without benefiting later requests. Starting with YJIT disabled and enabling it after application boot aims compilation at request code. The 37signals result is evidence for testing the method, not a promised Lambda percentage.

# Configure Ruby to start with YJIT disabled, then after Rails initializes:
RubyVM::YJIT.enable if defined?(RubyVM::YJIT) && RubyVM::YJIT.respond_to?(:enable)

Ruby runtime versions and Lambda support change. Confirm the deployed runtime, AWS base image, YJIT default, architecture, and gem native extensions. Rebuild container images to receive updated base-image patches; changing a tag in ECR does not redeploy an existing function by itself.

Decide with constraints, not fashion

Evidence for LambdaEvidence for a long-running service
Traffic arrives in bursts, so machines would otherwise sit mostly idle.Traffic stays steady enough to keep a small service busy efficiently.
Each HTTP request completes within the current integration and Lambda time limits and stores state externally.The app streams responses, holds WebSockets, runs long requests, or depends on local session memory.
The team already understands AWS events, IAM permissions, logs, traces, and deployment images.The team benefits more from connecting to one known process and inspecting it directly.
Queue consumers and scheduled functions can avoid booting all of Rails.A ten-line task pays the time and memory cost of a large Rails boot.
A measured test shows acceptable tail latency and complete-system cost.The decision depends only on the phrase "pay for what you use."

Calculate the complete system. Include the HTTP entry service, log ingestion and storage, provisioned concurrency, database or proxy charges, container builds, and data transfer. NAT means Network Address Translation. A function in a private network may send internet traffic through a billed NAT Gateway, which can change the cost calculation. Include staff time and tail latency. The p95 is the value that 95 percent of requests meet or beat; p99 uses 99 percent and exposes rarer slow requests. A small virtual machine or container service may be simpler and cheaper. Lambda wins when event integrations and automatic creation of parallel environments remove more work than they add.

The close

"The surprising part is how little adapter code Rack requires. That proves Rails can run here. It does not prove Rails should run here. Decide by tracing the incoming event, Rack conversion, job redelivery behavior, database path, time limits, and measured cost."

Self-test

Why can Rails run without Puma?

Rails is a Rack application. Lamby calls it directly after translating the AWS event, so no process needs to listen on an HTTP socket.

Is a container-image Lambda a normal Docker server?

No. Lambda still controls initialization and invokes the configured handler through the runtime API.

What is strange about Jets Mega Mode?

It starts a child Rack server inside the Lambda environment and uses writable /tmp for runtime needs.

Why can an SQS-driven job execute twice?

The side effect can finish before acknowledgment, or visibility can expire. Delivery is designed for retry, so effects must tolerate duplication.

Why enable YJIT after Rails boot?

It avoids spending compilation work on initialization paths that run once, while allowing later hot request code to benefit.
