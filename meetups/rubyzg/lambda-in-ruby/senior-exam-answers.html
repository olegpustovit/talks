Model answers

10 points

1. Separate the two lambdas

loose.call(1, 2) returns 1 because a plain Proc accepts extra positional arguments and ignores the second. strict.call(1, 2) raises ArgumentError because the lambda has strict arity of one. A return inside a lambda returns from the lambda. A return inside a plain Proc attempts to return from the method context that created it and can raise LocalJumpError when that context has gone. This teaches almost nothing about AWS internals. It is a naming joke plus a useful transition to input contracts. AWS Lambda's event model, isolation, lifecycle, and scaling do not derive from Ruby Proc semantics.

  • 3 points for call behavior.
  • 3 for return behavior.
  • 4 for limiting the analogy.
10 points

2. Trace cold, warm, and failed invocation

For A, Lambda prepares an execution environment, starts the container entrypoint and Ruby runtime, runs static code, then invokes the handler. Objects created outside the handler and files written under /tmp may remain when AWS freezes the environment after success. B can reuse them if AWS selects that warm environment. That reuse is possible, not promised, and the environment handles one standard invocation at a time. If C times out, Lambda reports an error and resets the environment. AWS documentation says reset behaves like shutdown, but does not clear /tmp before a possible later reuse. D may run in the reset environment or a different new one. Code must validate any cache and must never keep user correctness state only in memory or /tmp. Background work must finish before handler return.

  • 4 points for Init, Invoke, and reuse.
  • 3 for timeout and reset.
  • 3 for guarantee versus possibility.
10 points

3. Translate a request

Map the method to REQUEST_METHOD, path to PATH_INFO, raw query to QUERY_STRING, scheme to rack.url_scheme, and host and port to the Rack server keys. Normalize request headers into Rack's expected content keys and HTTP_* keys. Preserve cookies according to the payload version instead of joining them incorrectly. Base64-decode the body when the flag is true, wrap the resulting bytes in an IO-like rack.input, and set content length when appropriate. Rails returns status 201, headers, and an enumerable body. The adapter joins body chunks, closes the body when required, then returns the integration's status field, headers, cookies where supported, body string, and base64 flag if output is binary.

  • 5 points for request mapping.
  • 3 for binary, cookie, and repeated-value behavior.
  • 2 for response and body cleanup.
10 points

4. Explain why Puma disappears

API Gateway receives HTTP and invokes Lambda with an event. The Ruby runtime gives the event to the Lamby handler. Lamby creates a Rack environment and calls Rails.application.call in-process. It translates the returned Rack tuple into API Gateway's response. Puma is unnecessary because nothing inside the function listens for external TCP connections. Lambda already dispatches one event to the handler. Concurrent requests use concurrent execution environments. The architecture still needs owners for TLS termination, request-size and timeout limits, client disconnect behavior, access logs, authentication, header normalization, binary bodies, compression, and streaming limitations. API Gateway, Lambda, Lamby, and application code divide those jobs.

  • 5 points for the complete path.
  • 2 for concurrency.
  • 3 for remaining server responsibilities.
10 points

5. Compare three HTTP front doors

Do not choose from the short brief alone. Confirm whether "private" means no public endpoint, whether corporate identity uses an existing ALB-compatible identity provider or API Gateway authorizer, whether clients live inside the VPC, whether a private API endpoint is acceptable, and whether an ALB already exists. Confirm current timeout, payload, streaming, TLS, logging, and pricing rules. An ALB may fit an existing private network and corporate authentication setup. API Gateway may fit stronger API authorization and request controls. A Function URL is simple but may be wrong if the endpoint must be reachable only through a private corporate path or needs richer authorization. Estimate fixed ALB cost against request-based services at low traffic.

  • 4 points for missing facts.
  • 4 for service-specific reasoning.
  • 2 for current limits and cost checks.
10 points

6. Review global state

Assigning CURRENT_USER inside the method makes it a local variable in Ruby unless declared with constant syntax, and assigning to a constant during requests would produce warnings and shared mutable state. More important, request-specific user data must not live globally because a warm environment processes later users. Keep it local:

S3 = Aws::S3::Client.new

def handler(event:, context:)
  user = event.fetch("user")
  S3.put_object(
    bucket: ENV.fetch("BUCKET"),
    key: user,
    body: "ok",
  )
end

SDK clients, immutable configuration, parsed templates, and validated read-only caches are reasonable to reuse if their libraries support it. Credentials may refresh through the SDK. User records, authorization decisions, and uncommitted business state stay local or in durable external storage.

  • 3 points for Ruby scope behavior.
  • 3 for cross-invocation leakage.
  • 4 for a safe rewrite and reuse policy.
10 points

7. Pick a database path

Six hundred environments with one direct connection each can exceed a 300-connection database even before admin and other services. Set a Lambda Rails pool near one because each standard environment handles one invocation at a time, then cap reserved concurrency while testing. RDS Proxy can accept many client connections and reuse fewer database connections when transaction state allows, but long transactions and session-specific state reduce multiplexing. The Data API removes direct database sockets and uses HTTPS plus IAM and a secret ARN, but changes latency, transactions, response limits, and adapter compatibility. Test representative Rails queries and transactions for all viable paths. Measure connection storms, failover, cold connection latency, database CPU, and ambiguous errors. Start with a concurrency cap below safe database capacity and either RDS Proxy or a proven Data API adapter, then raise it from observed connection use.

  • 3 points for connection math and pool.
  • 4 for comparing proxy and API mechanisms.
  • 3 for safe rollout and failure tests.
10 points

8. Stop duplicate fulfillment

The label exists, but Lambda did not acknowledge the batch. When the SQS visibility timeout expires, the message can become visible and run again. Use an order-scoped shipment key with the carrier if supported. Store a shipment intent under a unique order key before calling, then store the carrier label ID. On an ambiguous timeout, query the carrier by the same key before creating a label. Make the database transition conditional so only one attempt moves the order from ready to shipping or shipped. Configure visibility longer than the credible processing time and extend it only with care. Report individual failed message IDs through partial batch response so successful siblings are not retried. Move a repeatedly failing message to a dead-letter queue after a chosen receive count and alert with enough order context to reconcile it.

  • 3 points for predicting redelivery.
  • 4 for idempotency and reconciliation.
  • 3 for batch and dead-letter behavior.
10 points

9. Design a cold-start experiment

Create four controlled configurations: each memory size with YJIT off, and each with the chosen YJIT timing. Keep image digest, architecture, region, Rails code, dependencies, database path, and HTTP front door fixed. Generate enough forced-new-environment requests to measure Init and end-to-end cold latency, then run sustained warm traffic to measure handler behavior after YJIT has time to compile hot methods. Record p50, p95, and p99, invocation duration, Init duration, billed duration, maximum memory, error rate, and HTTP client latency. Test realistic routes, payloads, database queries, and concurrency. Report cost per million requests plus provisioned-concurrency cost if used. A 40 percent mean improvement is incomplete if only one warm route was tested or p99 and cold cost worsened.

  • 4 points for controlled configurations.
  • 3 for cold and warm separation.
  • 3 for distributions, workload, and cost.
10 points

10. Choose the boring architecture

Keep the Rails web application on the existing virtual machines. Traffic is steady, so instances are used. Action Cable needs persistent WebSocket connections. Ninety-second requests require careful checking against each Lambda HTTP integration and are a poor fit for request-bound function work. The team already knows the deployment system, so a full migration adds operational learning without a stated measured problem. Candidate Lambda pieces include asynchronous report generation triggered through a queue, image transformations, inbound webhooks, or scheduled maintenance that does not boot all of Rails. Prototype one bounded task with a stable input, idempotent effect, timeout, and observable result. Move it only if end-to-end latency, failure recovery, monthly cost, and operational work beat the current job setup under production-like load.

  • 5 points for rejecting the full move using given constraints.
  • 2 for bounded candidates.
  • 3 for measurable migration evidence.
