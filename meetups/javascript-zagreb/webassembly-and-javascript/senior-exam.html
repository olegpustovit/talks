Part 1: numeric contracts

10 points

1. One word, three readings

Without running code, predict all four lines and explain each conversion:

const x = 0xffffffff;
console.log(x);
console.log(x | 0);
console.log(new Uint32Array([x])[0]);
console.log(new Int32Array([x])[0]);

Then explain why saying "the real value is -1" is wrong.

10 points

2. Audit a wrapping function

A teammate writes this C++ and promises that adding one to 2,147,483,647 returns -2,147,483,648 after compilation to Wasm:

int32_t add_one(int32_t x) { return x + 1; }

Identify the language-level problem. Supply a version whose wrapping contract is defined. Explain what JavaScript sees when the result crosses an i32 export.

Part 2: history and machine model

10 points

3. Why asm.js mattered

Explain x = x | 0 to a JavaScript developer at three levels: ordinary JavaScript behavior, asm.js validator meaning, and the limitation that motivated explicit Wasm types. Your answer must explain why old browsers could still run the function.

10 points

4. Module, instance, memory, table

A page creates two instances from one compiled Wasm module. Can the instances have separate mutable state? Can they share one memory? What is a table for? Why can neither instance call document.querySelector unless the host gives it a route to JavaScript?

Part 3: boundary incident

10 points

5. Find the stale view

const ptr = Module._make_histogram();
const histogram = Module.HEAPU32.subarray(ptr / 4, ptr / 4 + 256);
Module._process_large_image(imagePtr, imageLength); // may grow memory
console.log(histogram[0]);
Module._free(ptr);

Explain two independent lifetime hazards. Rewrite the sequence for a stable JavaScript-owned result.

10 points

6. Design the image API

You must grayscale a 24-megapixel RGBA image. Compare these APIs:

gray_pixel(r, g, b, a) -> packed_pixel
gray_image(ptr, byte_length, width, height) -> void

Choose one. Account for calls, allocation, copies, bounds validation, integer overflow in size calculation, ownership, and cleanup. State what you would benchmark.

10 points

7. Strings without hand waving

Describe every step required to pass the JavaScript string "Živjo 👋" to a C function accepting const char *. Include encoding, byte length, termination, allocation, call lifetime, and cleanup. Explain when the C function may retain the pointer.

Part 4: API and performance judgment

10 points

8. Pick an interop layer

You expose four numeric DSP functions and one C++ class with methods and internal state. Recommend raw exports, ccall/cwrap, Embind, or a mixture. Defend the choice using wrapper size, call frequency, type conversion, and object destruction.

10 points

9. Reject a weak benchmark

A benchmark runs Fibonacci once in JavaScript and once in Wasm after the Wasm module is already loaded. It reports "Wasm is 4.2 times faster." List the threats to that conclusion and design a benchmark that could support a production decision.

10 points

10. Architecture decision

A team proposes moving a form-heavy dashboard to Rust and Wasm because the page feels slow. Profiling shows 62 percent of time in network waits, 27 percent in layout and paint, 8 percent in JavaScript, and 3 percent elsewhere. Give a decision, an investigation plan, and the evidence that would make you reconsider.

Submission checklist

  • Every pointer has an owner and release point.
  • Every typed view has a validity condition.
  • Every speed claim names the measured interval.
  • Signedness is attached to an operation, not casually assigned to raw bits.
  • Wasm and JavaScript responsibilities remain separate.
